# VoiceNav Robot v1.0 product specification

**Status:** Approved target

**Current implementation:** See the
[architecture overview](../architecture/overview.md).

## Product outcome

A learner can hand-write, run, explain, and test a simulation-only ROS 2 robot
that turns a local Mandarin Voice Turn into a bounded Mission and executes it
through SLAM or Nav2 without granting the LLM motion authority.

The supported environment is deliberately narrow:

```text
Windows 11 host
WSL2 Ubuntu 24.04
ROS 2 Jazzy
Gazebo Harmonic
single analog microphone + analog speakers
local-only ASR, LLM, and TTS
```

## Approved capabilities

| Area | v1.0 behavior |
| --- | --- |
| Robot | Hand-written minimum differential-drive Xacro with collision, inertia, wheels, caster, odometry, TF, and 2D LiDAR |
| Voice | `voice_node`; 48 kHz mono PortAudio full duplex; pinned WebRTC APM 2.1; “小智”; 16 kHz sherpa-onnx KWS/ASR; Piper TTS; final-PCM AEC reference; barge-in |
| Agent | `agent_node`; STOP-first rules; clarification; official Qwen3-0.6B-GGUF Q8_0 through loopback llama-server; schema and semantic validation; capacity-1 latest-wins |
| Mission | One validated sequence of one to three semantic steps, single execution slot, feedback, timeout, cancel, and operational stop |
| Mapping | Separately launched slam_toolbox mode with bounded manual motion and named map saving |
| Navigation | Separately launched map server, AMCL, and Nav2 mode with Named Place navigation |
| Safety | Nav2/relative → Runtime generation filter → nav2_velocity_smoother → nav2_collision_monitor → `motion_gate_node` → diff_drive_controller; 250 ms Runtime authority lease, per-lease candidate data plane, and 0.35 s consumer timeout |
| Verification | In-memory dependency Adapters, contract tests, headless simulation smoke tests, and a documented WSL milestone flow |

## End-to-end acceptance flow

1. Start Mapping Mode and verify the robot, `/scan`, odometry, and the required
   TF chain.
2. Move the simulated robot with bounded semantic Mission Steps while
   slam_toolbox builds a map.
3. save a logical map name and verify the occupancy-map artifacts can be
   loaded.
4. stop Mapping Mode, start Navigation Mode, and verify AMCL is the sole
   `map → odom` owner.
5. say “小智，去书房”; local ASR and the Agent produce a typed Mission whose
   Named Place is resolved only in the trusted navigation implementation.
6. observe Mission feedback and success, then repeat with cancel, timeout,
   invalid-plan, busy, and operational-stop scenarios.
7. while TTS is playing, verify that its playback reference reaches AEC and
   does not create a false self-command; verify that a real Mandarin barge-in
   can cancel speech.
8. disconnect or stall Runtime or a command producer and verify the final
   velocity returns to zero through the independent authority or candidate
   deadline.

Every step must run without a cloud dependency. GUI and real-model checks may
be manual WSL milestone evidence, but deterministic fakes and headless
assertions remain the ordinary test path.

## Product invariants

- The self-written runtime processes are exactly `voice_node`, `agent_node`,
  `mission_runtime_node`, and `motion_gate_node`.
- Mapping Mode and Navigation Mode are separate process compositions; v1.0
  does not switch between them online.
- A Mission is semantic. It may contain move-distance, rotate-angle,
  navigate-to-place, and save-map intent; it never contains wheel speed or a
  final Twist.
- The local LLM may propose a Mission but cannot admit or execute it.
- A Mission is fenced by source instance/sequence and Runtime
  instance/admission epoch, then fully validated before its first side effect.
- At most one Mission is active. New work is rejected as busy, not queued or
  silently preempted.
- The operational-stop behavior uses the exact `StopMission.srv` type. It is
  an operational simulation stop, not a functional-safety emergency stop or a
  certified safety function.
- Audio device I/O and 10 ms PCM frames remain inside the Voice Module rather
  than crossing DDS.
- Target actuation uses gz_ros2_control and diff_drive_controller;
  ros_gz_bridge carries only `/clock` and `/scan`.
- Model weights, recordings, bags, generated private maps, and credentials are
  not repository content.

## Out of scope

- Real robot hardware, hardware drivers, functional-safety emergency-stop
  implementation, and safety certification.
- Camera, IMU/EKF, visual perception, arm, MoveIt 2, and manipulation.
- Online mapping/navigation mode switching and autonomous exploration.
- Cloud ASR, LLM, TTS, long-term conversation memory, accounts, and a Web UI.
- Custom SLAM back ends, model training, LoRA, and dynamic-obstacle research.
- Multi-robot operation and public network deployment.

## Definition of v1.0

v1.0 is reached only when the acceptance flow is reproducible from a clean
checkout, the stable Interfaces match their documentation, the complete
quality gate passes, real local voice models have milestone evidence, and the
release gate in the [release policy](../process/release-policy.md) is satisfied.

Project-specific terms use the [product glossary](glossary.md). Implementation
sources are collected in [engineering resources](resources.md).
