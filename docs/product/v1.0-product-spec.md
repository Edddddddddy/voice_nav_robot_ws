# VoiceNav Robot v1.0 产品规格

**状态：**已批准目标

**当前实现：**见[架构概览](../architecture/overview.md)。

## 产品结果

学习者能够手写、运行、解释和测试一个仅用于仿真的 ROS 2 机器人：它将本地中文 Voice Turn 转为有边界
Mission，并通过 SLAM 或 Nav2 执行，同时绝不将运动权限交给 LLM。

支持环境有意保持狭窄：

```text
Windows 11 host
WSL2 Ubuntu 24.04
ROS 2 Jazzy
Gazebo Harmonic
单个模拟麦克风与模拟扬声器
仅本地运行的 ASR、LLM 与 TTS
```

## 已批准能力

| 领域 | v1.0 行为 |
| --- | --- |
| Robot | 手写的最小差速 Xacro，包含 collision、inertia、wheel、caster、odometry、TF 与二维 LiDAR |
| Voice | `voice_node`；48 kHz mono PortAudio full duplex；固定 WebRTC APM 2.1；“小智”；16 kHz sherpa-onnx KWS/ASR；Piper TTS；最终 PCM AEC reference；barge-in |
| Agent | `agent_node`；STOP-first rule；澄清；通过 loopback llama-server 使用官方 Qwen3-0.6B-GGUF Q8_0；schema 和语义验证；capacity-1 latest-wins |
| Mission | 一个由一至三个语义步骤组成的已验证序列，具备单执行槽、反馈、超时、取消与运行停止 |
| Mapping | 独立启动的 slam_toolbox 模式，具备有界手动运动和具名地图保存 |
| Navigation | 独立启动的 map server、AMCL 与 Nav2 模式，支持 Named Place navigation |
| Safety | Nav2/相对运动 → Runtime 代际过滤器 → nav2_velocity_smoother → nav2_collision_monitor → `motion_gate_node` → diff_drive_controller；`250 ms` Runtime 权限租约、每租约候选数据平面与 `0.35 s` 消费者超时 |
| Verification | 内存内依赖 Adapter、契约测试、无头仿真冒烟测试与有记录的 WSL 里程碑流程 |

## 端到端验收流程

1. 启动 Mapping Mode，验证机器人、`/scan`、odometry 与所需 TF chain。
2. 用有界语义 Mission Step 移动仿真机器人，同时由 `slam_toolbox` 构建地图。
3. 保存逻辑地图名，并验证 occupancy-map artifact 可加载。
4. 停止 Mapping Mode，启动 Navigation Mode，验证 AMCL 是唯一的 `map → odom` owner。
5. 说出“**小智，去书房**”；本地 ASR 与 Agent 产出强类型 Mission，Named Place 仅在可信 navigation
   Implementation 内解析。
6. 观察 Mission feedback 和 success，再分别验证 cancel、timeout、invalid-plan、busy 和
   operational-stop 场景。
7. TTS 播放时，验证 playback reference 到达 AEC 且不会产生错误 self-command；验证真实中文 barge-in
   可取消 speech。
8. 断开或停滞 Runtime 或 command producer，验证最终速度通过独立 authority 或 candidate deadline 返回零。

每一步均不得依赖云服务。GUI 与真实模型检查可以作为手工 WSL milestone evidence，但确定性 fake 和
headless assertion 仍是常规测试路径。

## 关键验收指标

| 契约 | 目标 |
| --- | --- |
| Mission 大小 | `MissionStep[<=3]`，含一至三个语义步骤 |
| Agent pending queue | capacity 1，latest-wins |
| 音频设备 stream | PortAudio full duplex，48 kHz，mono |
| 音频 DSP frame | `10 ms / 480 samples`，48 kHz |
| KWS/ASR branch | 16 kHz mono |
| AEC dependency/reference | WebRTC APM 2.1；最终 application output PCM |
| Motion Gate authority lease | `250 ms` Gate steady clock；仅 Runtime 可续约 |
| Controller consumer timeout | `0.35 s` |
| Gazebo bridge target | 仅 `/clock` 与 `/scan` |
| Local LLM | 通过仅 loopback 的 llama-server 使用官方 Qwen3-0.6B-GGUF Q8_0 |

## 产品不变量

- 自编写 runtime process 严格为 `voice_node`、`agent_node`、`mission_runtime_node` 与
  `motion_gate_node`。
- Mapping Mode 与 Navigation Mode 是独立进程组合；v1.0 不在线切换两者。
- Mission 是语义性的：可包含移动距离、旋转角度、导航至地点与保存地图意图，
  绝不包含 wheel speed 或最终 Twist。
- 本地 LLM 可以提出 Mission，但不能准入或执行它。
- Mission 先经 source instance/sequence 与 Runtime instance/admission epoch fencing，再在第一个
  side effect 前完成全部验证。
- 至多一个 Mission 处于活动状态；新工作以忙碌状态拒绝，不能排队或静默抢占。
- 运行停止行为使用严格的 `StopMission.srv` 类型；它是运行仿真停止，不是功能安全紧急停止
  或认证安全功能。
- 音频设备 I/O 与 `10 ms` PCM frame 保留在 Voice Module 内，不穿过 DDS。
- 目标 actuation 使用 `gz_ros2_control` 与 `diff_drive_controller`；`ros_gz_bridge` 只承载
  `/clock` 与 `/scan`。
- 模型权重、录音、bag、生成的私有地图和凭据不是仓库内容。

## 非目标

- 真实机器人硬件、hardware driver、功能安全紧急停止实现和安全认证。
- Camera、IMU/EKF、视觉感知、arm、MoveIt 2 和 manipulation。
- 在线 Mapping/Navigation mode switching 与 autonomous exploration。
- Cloud ASR、LLM、TTS、长期对话记忆、账号和 Web UI。
- 自定义 SLAM back end、模型训练、LoRA 和动态障碍物研究。
- 多机器人运行和公网部署。

## v1.0 的定义

只有在干净 checkout 可复现端到端验收流程、Stable Interface 与文档一致、完整质量门禁通过、真实本地
语音模型具有 milestone evidence，且满足[发布策略](../process/release-policy.md)中的 release gate 时，
才达到 v1.0。

项目术语见[产品术语表](glossary.md)，实现来源见[工程资源](resources.md)。
