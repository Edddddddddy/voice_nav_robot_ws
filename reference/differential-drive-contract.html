差速驱动与里程计契约

VoiceNav Robot reference

坐标与符号

  • x 向前，y 向左，z 向上。
  • 线速度 v > 0 表示前进。
  • 角速度 ω > 0 表示从上方看逆时针，即左转。
  • r 是轮半径，L 是左右轮中心线的完整距离。

从底盘速度得到轮速

左轮线速度：v_left  = v - ωL/2
右轮线速度：v_right = v + ωL/2

左轮角速度：ω_left  = v_left  / r
右轮角速度：ω_right = v_right / r

直行时两轮同向同速；正角速度原地旋转时，左轮向后、右轮向前。 对当前机器人，r=0.035 m，L=0.40 m。

从轮速得到里程计速度

v = (v_right + v_left) / 2
ω = (v_right - v_left) / L

DiffDrive 对这些速度积分，得到连续的 odom → base_footprint 位姿。 轮径误差会影响直线距离与转角；轮距误差主要影响转角。 里程计可连续但会积累漂移，它不是全局地图定位。

分层 Interface

未来的上层控制
  │  ROS velocity command
  ▼
ROS–Gazebo adapter
  │  gz.msgs.Twist
  ▼
Gazebo DiffDrive
  ├─► wheel joints / physics
  ├─► Gazebo odometry
  └─► Gazebo pose transform

Gazebo topic 保持 model-scoped；下一层 adapter 再把它映射为稳定的 ROS topic。Mission、Agent 和语音模块不应知道 Gazebo topic， 也不应直接控制轮关节。

Topic 与 frame 所有权

  • Gazebo 输入： /model/voice_nav_robot/cmd_vel， 类型 gz.msgs.Twist。
  • Gazebo 输出： /model/voice_nav_robot/odometry， 类型 gz.msgs.Odometry。
  • 动态 frame：odom → base_footprint，只允许一个发布者。
  • 机器人内部 frame 仍由 URDF 与 robot_state_publisher 负责。
  • 未来若 EKF 接管 odom → base_footprint， 必须停止桥接 DiffDrive 的同一条 TF，避免双发布者。

停止与限速契约

  • 所有速度都必须经过配置上限，拒绝非有限数值。
  • 运动测试必须在正常路径和异常清理路径都发送零速度。
  • Gazebo DiffDrive 没有 command timeout，最后一条命令会继续生效。
  • 进入语音与 Nav2 前，ROS 运动出口必须加入可配置 watchdog； 上层任务超时不能代替底层速度租约。
  • 停止确认必须意味着安全出口已锁定并已请求零速度。

依据： Gazebo Sim 8 DiffDrive API 与 Nav2 Gazebo odometry setup。
